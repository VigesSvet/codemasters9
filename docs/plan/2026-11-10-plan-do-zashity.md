## Решение по стеку: статика A + FastAPI, без переписывания на React
**Почему не React сейчас:**
1. ТЗ §7.6 стек только рекомендует: «React, Next.js, Vue.js или аналогичные… допускается использование других технологий при обосновании». Баллы — за работающий функционал.
2. Перенос 31 страницы — 2–3 дня работы при нулевом видимом результате для жюри и риске сломать одобренный дизайн.
3. Главные дыры (каталог, ИИ, админка, данные) закрываются только бэкендом. React их не закрывает.

**Что делаем:** один процесс `uvicorn` (FastAPI) раздаёт `a-gos/` и `/api/*`; SQLite + FTS5, данные загружаются из `docs/research/current-site/content/*.json`. Статика ходит в API через `fetch`.

**Ответ жюри «почему не React»:** «Фронт отдаётся статикой ради скорости и SEO, бэкенд — FastAPI, как рекомендует ТЗ. Целевая архитектура: PostgreSQL + полнотекстовый поиск (OpenSearch), фронт постепенно переносится на React/Next — компоненты уже разделены».

**Опция, если останется время:** на React/Next переписать только каталог и карточку дела (самые интерактивные экраны), ~6–8 ч. Не раньше, чем закрыт P0.
