# Аудит прототипа против ТЗ и требований — 10.11.2026

Объект: `docs/mockups-v2/a-gos/` (вариант A, 31 страница + `admin/` 2 страницы), http://localhost:5190/. Защита 13.11.2026.
Метод: ТЗ прочитано целиком; прочитаны `app.js`, `index/katalog/delo/fond/filialy/istoriya/vystavka/ii/news/novost.html`, `admin/*`; секции `ob-arhive`, `uslugi`, `gostevaya`, `bazy`, `galereya` — по извлечённому тексту; Lighthouse (mobile, 17 страниц); скриптовая сверка `content/*.json` со страницами; свежие скрины (`/tmp/cm9audit/s/`) + `compare/v2-after/`. Код не менялся.

Оговорки метода:
- Lighthouse снят с `python http.server` (без gzip и кэша) — на нормальном хостинге цифры будут выше, но CLS и вес не исправятся сами.
- Сверка миграции — выборочное сравнение 40-символьных окон нормализованного текста; «потеряно» означает «текста нет ни в одной странице и не в `news-data.js`». Точность на уровне страницы, а не абзаца.
- Клавиатурная навигация и экранный диктор руками не проверялись; мобильная вёрстка оценена по скринам 390px, не на устройстве.

## 0. Вердикт

**Это хороший кликабельный макет, а не сайт.** Дизайн и перенос основного контента — сильные стороны. Но три вещи, которые ТЗ называет ключевыми (каталог, ИИ, админка), — имитация: 15 выдуманных записей, 3 заготовленных ответа, 2 статичные страницы без входа. Жюри из архивистов и ИТ это увидит за первые две минуты вопросов.

Оценка покрытия ТЗ по существу (не по наличию экрана): **~45%**. По «есть экран»: ~75%.

Что реально угрожает топ-1, по убыванию:
1. Каталог на выдуманных фондах (`Ф. 1-П`, `Ф. 18`, `Ф. 77-Ф`) и Семипалатинске, который с 2022 года в области Абай. Иллюстрации — Library of Congress, не ГАВКО.
2. ИИ — `if (/метрик/.test(q))`. Любой вопрос жюри не из трёх сценариев вернёт «открыт поиск по каталогу».
3. Нет бэкенда, БД, авторизации — весь §6 и §7.3 ТЗ не закрыты ничем, кроме картинки.
4. Lighthouse: 7 из 17 страниц ниже 80 по производительности (главная 62, новость 34).
5. Не перенесено ~115 страниц филиалов и полные тексты «История архива», «Деятельность», «Читальный зал» — при требовании «без потерь».
6. EN — только оболочка; весь перенесённый контент RU/KK. На KZ карточка дела наполовину русская.
7. Вся папка `docs/mockups-v2/` не в git (untracked). Один `rm` — и работы нет.

## 5. План до защиты

### Решение по стеку
**Не переписывать на React. Оставить статику как фронт и добавить тонкий FastAPI.**

Почему:
- ТЗ §7.6 стек только рекомендует («допускается использование других технологий при обосновании»). Оценивается работающий функционал, а не фреймворк.
- Перенос 31 страницы в React за 3 дня съест всё время и даст жюри ноль нового, плюс риск сломать одобренный дизайн.
- А вот отсутствие бэкенда закрывает половину ТЗ. FastAPI + SQLite (FTS5) из готовых `content/*.json` поднимается за день и превращает три имитации в три работающих модуля.

Что получится: один процесс `uvicorn`, который раздаёт `a-gos/` и `/api/*`. На слайде архитектуры честно: «сейчас SQLite + FTS, целевое — PostgreSQL + OpenSearch, фронт — постепенный перенос на React». Это обоснование, которое ТЗ допускает.

Чего не делать вообще: личный кабинет, IIIF-тайлы, OCR в реальном времени, лента соцсетей, 7 ролей с настраиваемыми правами, импорт Excel.
