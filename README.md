# Государственный архив ВКО — сайт и каталог

[![CI](https://github.com/saylaukhan/codemasters9/actions/workflows/ci.yml/badge.svg)](https://github.com/saylaukhan/codemasters9/actions/workflows/ci.yml)

## Вкратце

Сайт Государственного архива Восточно-Казахстанской области: публичный электронный каталог
с поиском, карточки дел и фондов, новости, филиалы, справочные страницы, ИИ-помощник и
административная панель для сотрудников архива. Переосмысление сайта e-arhiv.vko.gov.kz.
Для посетителей архива (граждан, исследователей) и сотрудников, которые наполняют каталог.
Стек: Python 3.12, FastAPI, SQLite с FTS5, статический web/ (HTML + JS без сборки), Docker.
Статус: рабочий прототип к защите 13.11.2026, подробная готовность модулей — в
[docs/READINESS.md](docs/READINESS.md).

## Детали

### Архитектура

Один процесс `uvicorn` отдаёт и статический сайт `web/`, и JSON API `/api/*`. ORM нет:
стандартный `sqlite3`, параметризованные запросы, схемы Pydantic v2. Фронтенд обращается к API
через `fetch` (`web/api.js`).

| Модуль `backend/app/` | Назначение |
|---|---|
| `main.py`, `config.py` | сборка приложения, настройки из переменных окружения, `/api/health` |
| `db.py`, `schema.sql` | подключение SQLite (WAL, foreign keys), схема, проверка наличия FTS5 |
| `search.py`, `textnorm.py` | полнотекстовый поиск, нормализация запроса и синонимы |
| `permissions.py`, `workflow.py` | матрица прав и переходы статусов публикации |
| `security.py`, `audit.py` | scrypt, сессии, лимит входов, CSRF, заголовки; журнал действий |
| `importer.py` | импорт описей из CSV/XLSX |
| `ai/` | ИИ-помощник: поиск фрагментов, локальные ответы, провайдеры |
| `routers/` | `catalog`, `branches`, `news`, `auth`, `admin`, `imports`, `ai`, `opendata`, `seo` |
| `static.py` | раздача `web/`, кэш-заголовки, страница 404 |

**База данных.** Иерархия фонд → опись → дело → документ (`fonds`, `inventories`, `units`),
файлы единицы (`files`), версии (`unit_versions`), пользователи и сессии, филиалы, новости,
журнал (`audit_log`), задачи импорта и виртуальная таблица `catalog_fts`. Схема и описание
таблиц — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Поиск.** SQLite FTS5 по опубликованным единицам; индекс обновляется при каждой смене
статуса. Запрос нормализуется (регистр, «ё», казахские буквы) и расширяется синонимами
старых и новых названий городов (например, Лениногорск/Риддер, Семипалатинск/Семей,
Усть-Каменогорск/Өскемен). Токены попадают в `MATCH` только в кавычках, длина запроса
ограничена. Если в сборке SQLite нет FTS5, поиск переключается на `LIKE`.

**Роли и workflow.** Роли: администратор, модератор, редактор, администратор филиала
(правит только свой филиал). Права проверяются на сервере в каждом обработчике, отказы
пишутся в журнал. Материал проходит путь `draft → review → approved → published`
(редактор готовит и отправляет на проверку, модератор проверяет и публикует; возможны
возврат на доработку и перенос в архив). Недопустимый переход — 409, нехватка прав — 403.

**Журнал и версии.** Каждое изменение единицы сохраняет снимок в `unit_versions`: данные,
автор, согласующий, комментарий, дата статуса. `audit_log` фиксирует тип операции, объект
и результат (успех или отказ); секреты в журнал не попадают.

**Раздельный доступ к описанию и файлу.** `units.pub_status` отвечает за публикацию
описания, `files.access` (`public` / `no_publish` / `needs_check`) — за выдачу файла. Файл
отдаётся, только если описание опубликовано и доступ `public`; проверка на сервере, прямая
ссылка закрытый файл не отдаёт. Публикация описания доступ к файлу сама не меняет.

**Импорт описей из Excel.** Загрузка CSV/XLSX, предпросмотр с автоподбором колонок и
проверкой строк (годы, дубликаты), затем применение: записи создаются черновиками, ошибка
строки не отменяет остальные, выдаётся протокол ошибок. Лимиты: 5 МБ, 5000 строк, 64 колонки.
Образец: `backend/seed/sample_import.csv`.

**Провайдеры помощника** (`AI_PROVIDER`):

| Значение | Поведение |
|---|---|
| `local` (по умолчанию) | без сети: поиск по открытым материалам (каталог, новости, филиалы) и шаблонные ответы на трёх языках |
| `ollama` | локальная нейросеть на сервере архива, запросы идут на `OLLAMA_BASE_URL`, данные не покидают сервер |
| `deepseek` | внешний API по ключу `DEEPSEEK_API_KEY` из окружения |

Ограничения общие для всех провайдеров. Помощник отвечает только по найденным
фрагментам и всегда помечает ответ как сформированный автоматически. Вопросы о персональных
данных и просьбы выдать закрытый файл, а также вопросы без найденных материалов
обрабатываются локально и во внешнюю или локальную модель не передаются. Модели уходят
только вопрос и заголовки опубликованных единиц с публичным файлом; список источников
собирается из БД, а не из ответа модели. На посторонние вопросы источники не выдаются. При
сбое провайдера помощник отвечает локальным шаблоном.

### Переменные окружения

Полный пример — `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_PATH` | `backend/data/archive.db` | путь к SQLite |
| `WEB_DIR` | `web` | каталог статики |
| `FILES_DIR` | `backend/data/files` | каталог файлов единиц |
| `AI_PROVIDER` | `local` | `local` / `ollama` / `deepseek` |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | адрес Ollama |
| `OLLAMA_MODEL` | `gemma4:26b` | модель Ollama |
| `OLLAMA_TIMEOUT` | `60` | таймаут запроса к Ollama, с |
| `DEEPSEEK_API_KEY` | не задан | ключ DeepSeek, только в секретах окружения |
| `DEEPSEEK_MODEL` | `deepseek-chat` | модель DeepSeek |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | адрес OpenAI-совместимого API |
| `SESSION_TTL_MIN` | `30` | автовыход при бездействии, мин |
| `LOGIN_MAX_ATTEMPTS` | `5` | неудачных входов на логин+IP |
| `LOGIN_WINDOW_MIN` | `10` | окно лимита входов, мин |
| `LOGIN_IP_MAX_ATTEMPTS` | `30` | неудачных входов с одного IP на все логины |
| `COOKIE_SECURE` | `false` | флаг Secure и HSTS; за reverse proxy с TLS — `true` |
| `FORWARDED_ALLOW_IPS` | `127.0.0.1` | адрес прокси, которому верим в `X-Forwarded-For` |
| `API_DOCS` | `false` | `true` открывает `/docs`, `/redoc`, `/openapi.json` |
| `SEED_PASSWORD` | `Demo-2026!` | пароль демо-пользователей |

Параметры запуска `make`: `PORT` (8000), `HOST` (127.0.0.1).

## Плюшки

- **Закрытый файл защищает сервер.** Выдача файла проверяется в обработчике (описание
  опубликовано и доступ `public`), иначе 403 (для неопубликованной единицы — 404, существование
  файла не раскрывается); прямая ссылка проверку не обходит. Поиск
  строится только по опубликованному.
- **179 автотестов** (pytest): права, workflow, поиск, импорт, помощник, безопасность,
  сквозной сценарий «редактор → модератор → публикация → поиск → файл → журнал → помощник».
- **CI** на каждый push и PR: ruff (проверка и формат), pip-audit по `requirements.txt`,
  pytest, smoke-проверка (seed, запуск uvicorn, запросы к API), html-validate по всем
  страницам, проверка локальных ссылок, сборка Docker-образа. Токен CI — только чтение.
- **Собственный аудит безопасности** от 12.11.2026: 21 находка (1 высокая, 7 средних,
  10 низких, 3 информационных). 12 исправлены полностью, 2 частично (общий демо-пароль,
  CSP с inline-скриптами), остальные — принятый риск или план. Регрессионные тесты —
  `tests/test_security.py`.
- **Работа без интернета.** Режим `local` не обращается к сети; шрифты и Leaflet лежат в
  репозитории. Локальная нейросеть через Ollama работает на сервере архива, данные
  наружу не уходят. Внешние сервисы нужны только для плиток карты, погоды и видео.
- **Открытые данные.** Опубликованный каталог выгружается целиком в CSV (UTF-8 с BOM,
  защита от формул) и JSON, без служебных полей: `/api/opendata/catalog.csv`,
  `/api/opendata/catalog.json`.
- **Доступность.** Три языка интерфейса (казахский, русский, английский), светлая и
  тёмная темы, версия для слабовидящих, адаптивная мобильная вёрстка.
- **Печать карточки с QR-кодом.** Карточка дела печатается отдельной формой с QR-кодом на
  страницу карточки.
- **«Как читать шифр».** В карточке дела раскрывающийся блок объясняет, из чего состоит
  шифр (фонд, опись, дело); у строки «Шифр» есть пояснение в глоссарии.
- **Помощник не выдаёт источники на посторонние вопросы:** релевантность считается по
  значимым словам запроса, без совпадений ответ «в открытых материалах ответа нет».

## Как запустить

Нужны Python 3.12 и `make`; `uv` ускоряет установку, но не обязателен. Для `make check-web`
и `make docker` — Node.js (`npx`) и Docker соответственно.

    make run      # с нуля: .venv, зависимости, демо-БД (если нет), сервер на :8000

Сайт: http://localhost:8000, Swagger: http://localhost:8000/docs (включается `make run`,
в продакшене `/docs` отвечает 404). Занят порт: `make run PORT=8001`.

| Команда | Действие |
|---|---|
| `make` / `make help` | список целей |
| `make demo` | пересоздать демо-БД и запустить |
| `make docker` | `docker compose up --build`, http://localhost:8000, БД и файлы в томе |
| `make test` | автотесты |
| `make lint` | ruff check и ruff format --check |
| `make check` | lint + test + проверка ссылок и html-validate |
| `make ollama` | сервер с `AI_PROVIDER=ollama` (см. ниже) |
| `make backup` | резервная копия БД в `backend/data/backups/` |
| `make clean` | удалить кэши и демо-БД |

**Демо-логины** (из `backend/seed/users.json`):

| Логин | Роль |
|---|---|
| `admin` | администратор |
| `moderator` | модератор |
| `editor` | редактор |
| `ridder` | администратор филиала Риддер |

Пароль у всех — `Demo-2026!`, меняется переменной `SEED_PASSWORD` при загрузке БД
(`SEED_PASSWORD=... make demo`). Пока действует демо-пароль, админка показывает баннер.

**Ollama (необязательно).** Установите Ollama на машину с сайтом, `ollama pull gemma4:26b`
(или другую модель через `OLLAMA_MODEL=...`), затем `make ollama`. Без Ollama команда
предупредит и запустит сервер, помощник ответит локальным шаблоном. DeepSeek: задайте в
окружении `AI_PROVIDER=deepseek` и `DEEPSEEK_API_KEY`.
